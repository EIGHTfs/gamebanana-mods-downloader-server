## 二、最终架构

```
gamebanana-mods-downloader-server/
├── server/                    # 服务端（零依赖 Node.js）
│   ├── app.js                 # HTTP 入口：路由/鉴权/静态页面/启动（含 HTML 反查路由）
│   ├── config.js              # 配置管理（config.json 自动初始化；读取游戏/映射）
│   ├── auth.js                # 密码 scrypt 哈希 + 会话（HttpOnly Cookie）
│   └── lib/
│       ├── gb-api.js          # GameBanana API 封装（resolveMod/搜索/NSFW 判定/Cookie/归档文件）
│       ├── mapping.js         # 映射与下载路径计算（仓库层/角色层/[作者] mod名）
│       ├── downloader.js      # 四步下载流程 + 并发/断点续传/重试/跳过/找回/归档
│       ├── search.js          # 按时间搜索（三时间字段 OR）
│       ├── merge-dirs.js      # 文件夹合并（英文目录 → 英文 – 中文，递归合并）
│       └── hash-index.js      # HTML 反查三索引（GB 表 + 本地表 + HTML 原名表）
├── json/
│   ├── gamebanana.com.json.example  # 示例配置（复制为 gamebanana.com.json 填真实路径）
│   ├── gb-hash-index.json     # GB 线上信息表（hash → mod 信息，随仓库共享）
│   ├── local-hash-index.json  # 本地表（hash → 实际下载位置，git 忽略）
│   └── html-name-index.json   # HTML 原名表（GB 短名/压缩包名 → mod，git 忽略）
├── mapping/                   # 每游戏一个 JSON：warehouses/roles/variants
├── electron/                  # 桌面应用版（Electron 主进程）
├── scripts/generate-mappings.js
└── 启动脚本（start-linux.sh / start-macos.sh / start-windows*.bat）
```

### 关键文件职责
| 文件 | 职责 | 备注 |
|---|---|---|
| `server/lib/gb-api.js` | GB API 封装 | `resolveMod` 带 cookie 拉 NSFW；`_aArchivedFiles` 归档文件也并入 files（archived:true） |
| `server/lib/mapping.js` | 路径计算 | `buildTargetDir`：仓库层映射 + 角色层「英文 – 中文」+ `[作者] mod名` |

| `server/lib/merge-dirs.js` | 文件夹合并 | 同名子目录**递归合并** + 删重复 description.html |

## 三、四步下载流程（用户定义，逐字为准）

输入 `https://gamebanana.com/mods/704164` 或纯数字 `704164`：

### ① 生成 HTML
- 拉 GB ProfilePage，生成 `description.html`：作者/游戏/分类/文件 MD5/图片/gif
- 算下载路径：`下载根目录 / 仓库层(映射) / 角色层(英文 – 中文) / [作者] mod名`
- **文件名一律按 GB 原名保存**（压缩包/图片/gif 都不重命名；图片就是 GB 短名 `_sFile`，不是内容 MD5）
- gif **初始不进 HTML**——下载成功后才以 GB 原名加入

### ② 查重归位
- 全游戏根目录按**文件名索引**（`rootNameIndex` 缓存，5 分钟 TTL）反查压缩包名/图片名
- 若存在于其他文件夹 → 整个文件夹 `mv` 到计算出的规范路径（文件全部保留，HTML 覆盖）
- 重复残留目录 → 游戏根 `.trash`（可恢复）
- **⚠️ 关键修复**：`wantFiles` 只含压缩包 + 图片（GB 短名），**绝不包含 gif 序列名**（`gif_001.gif` 任何 mod 都有，会误移大量无关目录！）

### ③ 整理阶段
- `.gbmd.part`：主文件 + part 都存在 → 删 part；仅 part → 保留（断点续传）
- **不再重命名图片为 md5**（旧逻辑的坑，见下文 bug 记录）

### ④ 正式下载
- 按 HTML 文件列表并发下载缺失文件（Range 断点续传、失败重试 3 次、停滞检测）
- 不改原始文件名，非法字符用空格替换
- **归档文件**（GB `_aArchivedFiles`）一并下载
- **gif 不强求**：失败自动跳过（不重试、不显示失败）
- **垃圾桶找回**：`.trash` 里有同名文件（含 `dup-归位-` 前缀目录）→ 自动找回而非重新下载

## 四、映射体系（核心）

### 文件：`mapping/<游戏名>.json`
```json
{
  "warehouses": { "characters": "角色", "weapons": "武器", "skins": "角色/.角色" },
  "roles": { "Sandrone": "桑多涅", "Varesa": "瓦雷莎" },
  "variants": { "桑多涅": "Sandrone", "danhenglunae": "Dan Heng Imbibitor Lunae" }
}
```
- **warehouses**：香蕉网大仓库 → 本地目录（`skins: "角色/.角色"` = 隐藏子目录，点开头）
- **roles**：角色英文 → 中文（目录名 = `英文 – 中文`）
- **variants**：搜索归一变体（中文/别名 → 规范英文）

### 代码内部默认映射（无 mapping JSON 时）
`Characters→角色`、`Weapons→武器`、`Skins→空`（Skins 层跳过）

### 各游戏映射约定
| 游戏 | 角色仓库 | 备注 |
|---|---|---|
| Genshin Impact（原神） | 角色 | 137 角色、736 变体 |
| Honkai Impact 3rd（崩坏3） | 女武神 | Characters/Skins → 女武神/.女武神 |
| Honkai Star Rail（星穹铁道） | 角色 | Weapons → 光锥 |
| Zenless Zone Zero（绝区零） | 代理人 | |
| Wuthering Waves（鸣潮） | 共鸣者 | |

### ⚠️ 关键踩坑：GB 全名 vs 映射短名
- GB 角色分类用**全名**（`Sangonomiya Kokomi`、`Kaedehara Kazuha`），映射若只有短名（`Kokomi`、`Kazuha`）→ 归一匹配失败 → 落英文裸目录
- **补全名变体**：roles 加全名 key（`Sangonomiya Kokomi → 珊瑚宫心海`）
- 实测：补 10 个全名映射后 Kokomi 正确落 `角色/Sangonomiya Kokomi – 珊瑚宫心海/`

## 五、HTML 反查（三索引）

网页「设置 → HTML 反查」：输入文件 MD5 **或图片原始短名**（GB 原名）反查所属 mod。

| 索引 | 文件 | 内容 | git |
|---|---|---|---|
| GB 线上信息表 | `json/gb-hash-index.json` | hash → mod 名/作者/游戏/链接/GB 文件名 | ✅ 随仓库共享 |
| 本地信息表 | `json/local-hash-index.json` | hash → 本机实际下载目录/文件名 | ⛔ git 忽略 |
| HTML 原名表 | `json/html-name-index.json` | GB 原名（图片短名/压缩包名）→ mod | ⛔ git 忽略 |

**查询顺序**：本地表 → GB 表 → HTML 原名表（短名可忽略后缀匹配）。
**重建**：`/api/hash-rebuild` 全量扫 description.html（6000+ HTML 热缓存 ~1 秒）。
**关键修复**：rebuild 额外扫描 mod 目录磁盘 md5 名图片（文件名=内容 hash），垃圾桶文件反查命中率 15.9% → 90%。

## 六、关键 bug 修复记录（全是血泪，别重蹈）

### 1. step2 gif 通用名误移（最严重）
- 现象：下载莫娜 mod 时 6 个**无关 mod 目录**被整体移进莫娜目录，Xilonen 目录被删壳
- 根因：`wantFiles` 含 `gif_001.gif`（通用名）→ 全根反查把所有含该文件的目录命中
- 修复：gif 不参与 wantFiles；找回用严格正则（防子串误配 `skimpy_mona.zip` ⊂ `thicc_skimpy_mona.zip`）

### 2. 图片 md5 重命名 → 垃圾筒爆炸
- 现象：4.6GB 垃圾筒、2612 张 jpg
- 根因：旧逻辑把图片重命名为内容 md5，旧 HTML 无 hash → 重复下载 → 去重丢 trash
- 修复：**图片按 GB 原名（`_sFile` 短名）保存，不重命名**；下载时 GB 名存在即跳过

### 3. verifyModCompleteness/verifyGifs（macOS 会话加回的错误）
- 现象：下载完"完整性校验"把已存在图片判缺失 → 重复下载
- 修复：**彻底移除**（用户明确要求）；旧序列图/重复图改手动清理

### 4. 归档文件（`_aArchivedFiles`）
- 现象：GB 更新文件名后（`_7e4c1` → `_101`），垃圾桶旧版匹配不上
- 修复：gb-api 把 `_aArchivedFiles` 并入 files（archived:true）→ 归档文件也作为下载项按原名处理

### 5. 文件夹合并不递归
- 现象：`角色/Chasca/` 与 `角色/Chasca – 恰斯卡/` 同名子目录合并后英文目录还在
- 修复：`mergeTree` 递归合并同名子目录内容 + 删重复 description.html

### 6. 重启后下载列表消失
- 现象：重启后 paused/done 任务被当残留清掉
- 修复：`restorePendingTask` 保留 paused/done（列表可见），running 继续下载，仅 preparing 无 items 清理

### 7. 并发上限
- 现象：手动改 32 无效
- 修复：`setConcurrency` + 运行时限流 + 启动读取 **3 处上限统一 16 → 32**

### 8. hash 表被清空
- 现象：SA6400 的 gb-hash-index.json 只有 1 条（应该 5000+）
- 修复：从本机同步 5267 条 GB 表；重建本地表 11135 条 + HTML 原名表 30741 条

## 七、用户铁律（必须遵守，违反会被骂）

1. **密码可不设置**：初次未设密码 → 只警告、直接可用（不强制 setup）

11. **镜像规模要准**：README 里映射规模（137/736）等数字要跟实际一致
