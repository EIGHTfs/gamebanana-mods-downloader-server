## 1. 项目结构

```
gamebanana-mods-downloader-server/
├── server/

│       ├── hash-index.js       # hash 反查（GB 表/本地表/HTML 名表）

│   ├── gamebanana.com.json     # 游戏配置（id/cn/downloadPath，gitignored）
│   ├── gb-hash-index.json      # GB 信息表（hash→mod，提交 git）
│   ├── local-hash-index.json   # 本地表（hash→本地路径，gitignored）
│   ├── html-name-index.json    # HTML 名表（GB 原名→mod，gitignored）
│   └── role/<游戏名>.json      # 角色列表缓存（每游戏一文件）
├── server/public/              # 前端（index.html + app.js）
└── start-linux.sh              # Linux 启动脚本
```

## 4. 认证与鉴权

- 首次未设密码 → 登录直接成功（`noPassword: true`），仅警告。
- 已设密码 → `POST /api/login` 带 `{"password":"..."}`，返回 `Set-Cookie: session=...`。
- 所有 `/api/*`（除 login/logout/status）需鉴权：请求带 cookie（`-b cookies.txt`）。
- 无密码时 `requireAuth` 直接放行。

**调用示例：**

```bash
### 油猴脚本下载入口（2026-09-01）

- 页面顶部「📥 油猴脚本」按钮 → `GET /userscript`（别名 `/userscript.user.js`、`/gamebanana-cookie-userscript.user.js`）
- 返回 `scripts/gamebanana-cookie-userscript.user.js`（**单一来源**：脚本只放项目根 `scripts/`，本地与 SA6400 同源），
  `Content-Type: text/javascript` + `Content-Disposition: attachment` 强制下载。
- 脚本用途：浏览器打开 gamebanana.com 后点右下角 🍌，检测登录态/用户名 + 复制完整 Cookie（含 HttpOnly，供 GameBanana Mod Downloader 填 `gbCookie`）。
- 参照实现：iwara-downloader 的 `/userscript` 路由。

# 登录（保存 cookie）
curl -c /tmp/gb.c -X POST http://127.0.0.1:8642/api/login \
  -H 'Content-Type: application/json' -d '{"password":"AR-26710"}'

# 带 cookie 调 API
curl -b /tmp/gb.c http://127.0.0.1:8642/api/task
```

## 5. 设置类 API

### GET /api/settings

返回 `{ ok, settings }`。

**2026-09-01 脱敏**（参照 iwara-downloader-server）：settings **不回传 `gbCookie` 明文**，改用 `hasGbCookie` 布尔标记（`true` = 已配置 cookie）；同时不含 passwordHash/passwordSalt。前端永远拿不到明文去覆盖。

```json
{ "ok": true, "settings": { "hasGbCookie": true, "downloadConcurrency": 32, "sessionHours": 72, "port": 8642 } }
```

### POST /api/settings

允许字段：`gbCookie`、`downloadConcurrency`、`sessionHours`、`port`。

**2026-09-01 语义**：
- **敏感字段 `gbCookie` 为空串/空白时跳过不覆盖**——留空 = 不改（避免用户误清空已有 cookie）。
- 支持**油猴/手填组合文本**（形如 `Cookie=sess=...; rmc=...` 的多行文本），后端用 `parseCredentialText()` 提取 `Cookie=` 值，**非空才写**。
- 返回脱敏后的 settings（同 GET）。

```json
{ "downloadConcurrency": 32, "gbCookie": "sess=...;rmc=..." }
```

前端（真实 + 模板）配套行为：保存成功后**清空 cookie 输入框、placeholder 变为「已保存（再贴新凭证才会覆盖；留空不改）」、显示「已保存」提示**，并刷新顶部用户名；输入框只在为空时回填一次（`dataset.filled` 标记），不会把旧值盖回刚粘贴的新凭证。

### POST /api/change-password

```json
{ "password": "新密码" }
```

### GET/POST /api/games

读取/写入 `json/gamebanana.com.json`，结构：

```json
{
  "Genshin Impact": { "id": 8552, "cn": "原神", "downloadPath": "/volume6/.../Mods" },
  "Zenless Zone Zero": { "id": 19567, "cn": "绝区零", "downloadPath": "/volume6/.../Mods" }
}
```

`downloadPath` 是**下载根目录**（映射后的仓库层会建在其下）。

## 6. 游戏/映射/角色 API

### GET /api/mapping

返回 `{ ok, games: { 游戏名: {warehouses, roles, variants} } }`。

### POST /api/mapping/add-role

```json
{ "game": "Zenless Zone Zero", "en": "Ellen Joe", "zh": "艾莲·乔" }
```

写入 `mapping/<游戏名>.json` 的 roles。

### GET /api/gb-characters?game=<游戏名>[&refresh=1]

- 返回 `{ ok, count, characters: [...], fromCache }`。
- **默认读 JSON 缓存** `json/role/<游戏名>.json`（秒回）。
- `refresh=1` 强制从香蕉网重新拉取并写回缓存。
- 角色来自 GB 的 `_aSubCategory`（Characters/Skins 大仓库下的子类）+ 本地 mapping roles 补全。
- 缓存文件：`json/role/Genshin Impact.json` 等（每游戏一文件，key 为游戏名，含 gameId/characters/at）。

### GET /api/gb-game-info?id=<gameId>

返回 `{ id, name, roots: [{id, name, itemCount, categoryCount}] }`（根分类/仓库）。

### GET /api/gb-warehouses?game=<游戏名>

返回 `{ ok, warehouses: [{name, type, local, from}] }`（含映射本地名标注）。

### GET /api/gb-login-status

检测 GB cookie 是否有效，并返回当前登录用户信息。

**2026-09-01 改为真实会话端点**（旧实现：拉 NSFW mod 708465 看能否拿到 `_aFiles`+`_sInitialVisibility=hide`，实测匿名也拉得到会误判，已弃用）：

1. `GET https://gamebanana.com/apiv13/Member/UiConfig?_sUrl=%2F` → `_bIsLoggedIn`（是否登录）、`_idMemberRow`（当前用户 id）
2. `GET https://gamebanana.com/apiv13/Member/{id}/ProfilePage` → `_sName`（用户名）、`_sProfileUrl`

**关键坑（2026-09-01 用户发现，已实测确认）**：GameBanana 会话绑定创建会话时的**浏览器 User-Agent**。
用纯 Chrome UA 请求即使 cookie 正确也判 `_bIsLoggedIn=false`；必须用**登录时浏览器同款 UA**（用户用 Edge 登录 → 必须带 `Edg/` 标识，如
`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36 Edg/126.0.0.0`）才会被识别。
UA 在 config 的 `gbUserAgent` 配置（默认 Edge UA），`server/lib/gb-api.js` 的 `fetchJson` 统一读取；换了登录浏览器记得同步改。

**cookie 只需 `sess` + `rmc` 两个**（实测确认）：其余 `_ga`/`connectId` 等分析 cookie 不需要，配合正确 UA 即可识别登录态。

**顶部用户名（2026-09-01 用户要求）**：页面顶部 header 在时间（`#serverTime`）前显示当前登录用户名
（`#gbUserBadge`，如 `👤 fluquor`），数据来自 `GET /api/gb-login-status` 的 `username`；保存 cookie 后会即时刷新。
真实前端（`server/public/`）与模板（`docs/ui-template/`）同步实现。


响应：
```json
{ "ok": true, "configured": true, "loggedIn": true,
  "username": "fluquor", "idRow": 2330203,
  "profileUrl": "https://gamebanana.com/members/2330203",
  "detail": "已登录：fluquor" }
```
未登录时：`loggedIn:false`，detail 提示会话失效或 cookie 不完整（GB 会话含 HttpOnly cookie，需用浏览器 DevTools 或油猴 GM_cookie 复制完整 cookie）。

## 7. 搜索 API

### GET /api/keyword-search?q=<关键词>&game=<游戏名>[&perpage=50][&max=100]

**合并搜索**（2026-08-27 改进）：

- `q` 先归一化（中文 → 英文，`normalizeKeyword`，如 桑多涅 → Sandrone）。
- 自动生成**变体**（`genVariants`）：原词 + 短名（Jane Doe → Jane）+ 中文（roles 反查 简·杜/简）。
- 每个变体分页搜索，按 modId **去重合并**。
- 返回：`{ ok, count, results, variants, normalized }`。

```json
{
  "ok": true,
  "count": 17,
  "variants": ["Jane Doe", "Jane", "简·杜", "简"],
  "normalized": { "from": "简·杜", "to": "Jane Doe" },
  "results": [{ "modId": "545921", "name": "Doppelganger Jane...", "author": "...", "profileUrl": "...", "game": "Zenless Zone Zero", "isNsfw": true }]
}
```

> 关键词搜索只按**标题**匹配（GB 搜索 API 限制）。要拉某角色**全部** mod，用按时间全量搜索或后续的"按角色分类浏览"（`fetchModsByCategory`）。

### POST /api/search

按时间搜索。body：

```json
{
  "games": ["Zenless Zone Zero"],
  "startDate": "2000-01-01",
  "endDate": "2026-08-28",
  "contentFilter": ["normal", "nsfw"]
}
```

后台每秒 1 页，结果存 `search_cache.json`。

### GET /api/search-status

返回 `{ ok, task }`（搜索任务状态/进度）。

### POST /api/search/stop

停止搜索（保留已找到结果）。

### GET /api/search/cache

返回 `{ ok, cache: {results, startDate, endDate, contentFilter, queryTime} }`。

### POST /api/search/clear

清空搜索缓存。

### POST /api/search/import

导入搜索记录（JSON 数组 / `{results:[...]}` / `{records:[...]}`）。按 modId 合并，**导入覆盖原有**。

```json
{ "records": [{ "modId": "561629", "name": "...", "author": "...", "profileUrl": "...", "dateAdded": 1700000000 }] }
```

返回 `{ ok, added, replaced, total }`。

### GET /api/search/export

下载当前搜索记录 JSON（Content-Disposition attachment）。

## 8. 下载/任务 API

### POST /api/download

body：`{ "links": ["https://gamebanana.com/mods/561629", "561629", ...] }`

- 支持完整链接或纯数字 id。
- 返回 `{ ok, started, task }`。
- **追加语义**：已有任务则把新链接 append 到 `pendingMods`；paused 状态提交自动恢复下载。

### POST /api/download-selected

body：`{ "items": [{ "profileUrl" 或 "modId": "..." }, ...] }`（搜索结果勾选下载）。

### GET /api/task

返回完整任务对象：

```json
{
  "ok": true,
  "task": {
    "status": "running|preparing|paused|done|stopped|error",
    "message": "...",
    "pendingMods": [{ "profileUrl": "...", "name": "..." }],
    "buildIndex": 36,
    "items": [{ "type": "file|image", "displayName": "...", "path": "...", "url": "...", "modName": "...", "targetDir": "...", "modId": "...", "_skip": false }],
    "resultsMap": { "0": { "ok": true, "skipped": false, "exists": false, "path": "..." } },
    "doneCount": 47,
    "activeItems": [{ "idx": 3, "name": "...", "received": 1024, "total": 2048, "speed": 500000 }],
    "preparingItem": { "name": "...", "type": "preparing" },
    "concurrency": 32,
    "abort": false, "pause": false
  }
}
```

**前端轮询**：每 2 秒 GET /api/task，`renderTask` 渲染（有指纹缓存优化，千项任务不卡）。

### POST /api/task/pause | resume | stop

无 body。pause 暂停（保留列表）；resume 继续；stop 终止（**彻底中断下载**，清空列表）。

### POST /api/task/retry-failed

**2026-09-01 起支持单项重试**（body 可选）：

```json
// 全量重试失败项/卡住项（无 body 或 {}）
{}
// 单项重试（只重试 url 或 path 匹配的那一项，行级🔄按钮用）
{ "url": "https://images.gamebanana.com/...", "path": "/volume6/.../file.zip" }
```

**2026-09-01 修复（重试多个 bug，见决策 #12）：**
- 旧：行级🔄单项重试也调此接口且无 body → 变成全量重试（所有失败项都重新入队）
- 旧：全量重试把「未开始」项（任务 running 中无结果）也重试（本会继续下载，重试无意义）
- 旧：全量重试把 `type:"error"/"skipped"`（构建失败/去重跳过/图床不可达）也重试（重试必再失败）
- 旧：重试后未重置 `task.results` 旧快照 → 前端 `resultOf` 回退到旧数组，状态仍显示失败
- 新：行级🔄 传 `{ url, path }` 单项重试，只匹配那一项；空 body = 全量
- 新：全量只重试「确实失败 `r.ok===false`」或「卡住（任务已结束无结果残留）」；running/preparing 中
  无结果的项=未开始，不重试（本来就会继续下载）
- 新：重试后清 `task.results` + 重算 `doneCount`/`currentIndex`，前端状态正确重置

### POST /api/task/concurrency

```json
{ "concurrency": 32 }
```

1~32，写 config 持久化（下次任务也生效）。

### GET/POST /api/task/restore-mode

- GET：`{ ok, restoreOnly: bool }`
- POST：`{ "enabled": true }` → `{ ok, restoreOnly }`

**找回模式**：开启后下载任务**不实际下载**，只做 prepareMod 的垃圾桶找回/归位/HTML 生成，需下载的项直接标记跳过。**默认关闭**。前端开关**仅无任务时**可改（任务运行/暂停/完成时禁用）。

### POST /api/skip

body：`{ "url": "...", "path": "..." }`。跳过单项（标记 skipped，前端立即消失）。

### POST /api/skip-all-failed

无 body。跳过全部失败项。

**2026-09-02 修复（用户反馈：错误项不能清除）**：
- 旧：`skipAllFailed` 里 `if (!item || !item.path) continue` 把 `type:"error"` 且 `path=""`
  的错误项（构建失败，只有 mod url）排除 → 前端也无按钮 → 用户「不能清除」
- 新：去掉 `!item.path` 限制；无 path 错误项按 `url` 匹配即可标记跳过（清除）
- 前端：错误项（无 path）行显示「🚫 清除」按钮（调 `/api/skip` 传 `{ url }`）；有 path 失败行不变
- SA6400 实测：3 个真实错误项（639650/615536/607848）全部清除成功（`skipped:true`）

### 错误文本点击复制（2026-09-02 新增）

前端任务列表：失败/错误行的状态文本（如 `Unexpected end of JSON input`、`This operation was aborted`）
渲染为可点击元素 `.mm-err-copy`，点击复制错误内容到剪贴板并 toast 提示「已复制错误文本」。
兼容 http（非安全上下文）——clipboard API 不可用时回退 `document.execCommand("copy")`。

## 11. 下载流程详解（重点）

下载是**四步流程**，核心在 `server/lib/downloader.js` 的 `prepareMod(url)`，由任务循环（produce + consume 双协程）驱动。

### 11.1 任务生命周期

```
POST /api/download
  └─ startDownloadTask({mods})
      ├─ 任务对象写入 download_task.json（持久化）
      ├─ runDownloadLoop() → doDownloadLoop()
      │   ├─ 生产者 produce（串行）：逐个 pendingMods → prepareMod
      │   │   └─ 每个 mod 生成 items（下载项），push 到 task.items
      │   └─ 消费者 consume（并发 N 线程）：取 items → executeDownloadItem
      │       ├─ _skip/exists → 跳过（已存在/找回）
      │       ├─ restoreOnly → 跳过（找回模式）
      │       └─ 否则 → downloadToFile（断点续传下载）
      └─ 全部完成 → finalizeHtmls（写 hash/还原 md5 名/追加旧文件）
```

### 11.2 四步流程（prepareMod）

#### 第一步：生成 HTML + 算下载路径（genIndexHtml）

1. `gbApi.resolveMod(url)`：拉 GB ProfilePage，解析 mod 元数据 + 文件列表（含 `_aArchivedFiles` 归档文件）+ 图片（`_sFile` 短名）+ gif。
2. `mapping.buildTargetDir(mod)`：算下载路径
   - 根 = `gamebanana.com.json` 的 `downloadPath`
   - 仓库层 = `warehouses` 映射（characters→角色/代理人，skins→角色/.角色 等）
   - 角色层 = `roles` 映射（英文 → `英文 – 中文`）
   - 文件夹 = `[作者] mod名`
3. 生成 `description.html`（含 `<script id="gbmd-index">` JSON 索引块，机器可读）。
4. **HTML 文件记录追加合并**：旧 HTML 的 legacy 文件保留 + 网上新文件追加/更新（作者删掉的文件仍记录）。

#### 第二步：查重归位（findExistingDir + moveDirTo）

- 用**全根文件名索引**（`rootNameIndex`，缓存 5 分钟）反查 wantFiles（压缩包名 + 图片短名）。
- 找到"旧目录"（文件名匹配但位置不对）：
  - **文件夹名 = `[作者] mod名` 或 `mod名`** → 整夹移动到计算路径（moveDirTo）。
  - **非 mod 名目录**（可能是别的 mod 的正确目录）→ **只移动匹配文件本身**，不整夹移动、不删其 HTML。
  - **裸仓库目录**（角色/代理人等分类层）→ 移动匹配文件本身 + 删仓库根 HTML。
  - **抽文件前检查源目录有无 description.html**：有 HTML（完整 mod 目录）→ 跳过不抽（防共用图被抢）；无 HTML（残留）→ 才抽。

#### 第三步：整理阶段（integrityCheck + trash-restore + auto-organize）

1. **part 文件处理**：主文件 + part 都在 → 删 part；仅 part → 保留（断点续传）。
2. **垃圾桶找回（trash-restore）**（重要）：
   - 递归扫描游戏根 `.trash` 全部子目录（含用户手动放的 `垃圾桶/`）。
   - 按**文件名匹配**找回：
     - 直接同名
     - `dup-归位-xxx-原名` / `dup-仓库散落-ts-原名` 前缀
     - **核心名模糊匹配**（coreName）：去年份前缀 `2026_`、去尾部 `_哈希` 后缀、去 `_-空格`。例：垃圾桶 `bottom_heavy_furina_top_heavy_.zip` → 找回改名 `2026_bottom_heavy_furina_top_heavy__576b7.zip`。
   - 按内容 hash 找（md5 名文件）。
   - 找回成功 → 文件不再重新下载（标记 exists）。
3. **自动整理（auto-organize）**：
   - 扫描 mod 目录，不在 HTML 列表（files/images/gifs）的文件：
     - 反查 name-index 命中且 modId == 当前 mod → **旧版本，保留**（追加 HTML legacy）。
     - **压缩包（zip/rar/7z）反查不到 → 也保留**（防误清旧版本）。
     - **图片类不在列表 → 移入垃圾桶**，**保留来源目录结构**（`trash/<relDir>/<文件名>`）。
   - **在 trash-restore 之后执行**（否则移入垃圾桶的 md5 名文件会被 trash-restore 捞回）。

#### 第四步：正式下载（buildDownloadItems + consume）

- 构建下载项：files（zip/rar/7z）+ images（jpg/png）+ gifs。
- 已存在（路径存在且 size>0）→ `_skip`，标记 exists。
- 图片额外兼容：内容 hash 记录存在且同内容 md5 名文件在 → 也跳过。
- 仅 part 存在 → 不跳过（断点续传）。
- `downloadToFile`：HTTPS keep-alive 连接池（`HTTPS_AGENT`，首连 28-30s，复用 0.7s）+ Range 断点续传 + 失败重试 3 次。
- **文件名一律按 GB 原名**（不重命名）。Windows/Linux 非法字符 → 空格。
- **gif 失败自动跳过**（仅 gif；压缩包/图片失败正常重试显示失败）。

### 11.3 下载完成后（finalizeHtmls）

- 把成功下载的文件 hash 写进 HTML files/images 记录。
- HTML 只显示**下载完成的** + 追加旧文件（磁盘存在但 HTML 未记录的压缩包/图片 → legacy）。
- **md5 名图片还原**：HTML 记录 hash（内容 md5）+ file（GB 原名），若磁盘有 `hash.jpg` → 重命名为 GB 原名。

### 11.4 找回模式（restoreOnly）

- 开启后：consume 的 `executeDownloadItem` 开头检查 `settings.restoreOnly` → 需下载的项直接返回 `{ok, skipped, skipReason:"找回模式"}`。
- 任务创建时 `pendingMods.reverse()` → **旧的 mod 先处理**（列表新的在前，倒序后旧的先找回）。
- 效果：全量搜索列表 + 找回模式 → 秒级跑完，把垃圾桶里能匹配的文件全部归位，不下载任何文件。
- 之后关掉找回模式，正常下载剩余缺失文件。

## 12. 找回模式（垃圾桶找回）

### 垃圾桶结构

- 游戏根 `.trash/`：下载器自动清理/归位产生的文件。
- 用户手动整理：`.trash/垃圾桶/角色名/[作者] mod名/...`（可含完整目录结构）。
- trash-restore **递归扫描全部子目录**，只按文件名匹配，不判断文件夹深度。

### 归位逻辑

1. prepareMod 第二步/第三步时，wantList（HTML 里的文件）逐个匹配垃圾桶。
2. 匹配成功 → rename 到目标目录，**改名 GB 当前名**（coreName 模糊匹配）。
3. 文件已存在（目标目录有）→ 跳过。

### 实测示例

- `bottom_heavy_furina_top_heavy_.zip` → `2026_bottom_heavy_furina_top_heavy__576b7.zip`（mod 482806）
- Belle 系列 52 个文件从垃圾桶归位到 `代理人/Belle – 铃/[作者]...`。

## 14. 注意事项/坑

1. **CIFS 挂载不能 chmod**：通过 NAS 挂载（`/vol02/...`）编辑文件 OK，但 **git init/commit 会因 config.lock EPERM 失败**。git 操作必须在 SA6400 上 SSH 执行。
2. **node 不在 PATH**：SA6400 的 node 在 `/var/packages/Node.js_v20/target/usr/local/bin/node`。SSH 命令里用完整路径或先 `export PATH`。
3. **重启服务器**：kill 旧 PID（`netstat -tlnp | grep :8642`）→ sleep 2 → `nohup node server/app.js > server/server.log 2>&1 &`。重启后 `restorePendingTask` 把任务恢复为 **paused**（不自动续跑，需网页点继续）。
4. **浏览器缓存**：改前端后必须更新 `index.html` 里 `app.js?v=版本号`，否则用户看不到新代码。
5. **console.log 缓冲**：nohup 下 prepareMod 的日志（trash-restore 等）可能不实时进 server.log，不影响功能。
6. **GB API 限流**：搜索/Index 分页太快会 400/429。搜索 1 页/秒；建索引页间隔 350ms。
7. **文件名一律 GB 原名**：绝不重命名（除非法字符→空格）。旧 md5 名文件是历史遗留，auto-organize 会处理。
8. **旧版本文件不能清**：作者更新只保留新版本，旧版本 zip 从 GB 页面消失但本地保留——auto-organize 对压缩包一律保留（name-index 反查同 modId 或直接保留）。
9. **找回模式**：默认关闭；开启后不下载只归位；**仅无任务时可切换**。
10. **合并搜索**：搜角色自动补变体（短名/中文），结果去重合并。但关键词搜索只按标题匹配，要全量用按时间搜索。
11. **角色列表缓存**：`json/role/<游戏名>.json`，默认秒回；设置页"🔄 重新获取角色"强制刷新。
12. **垃圾桶**：用户手动整理的 `垃圾桶/` 子目录是**找回数据源**，不要清理；下载器自动移入的 `.trash/` 文件保留原名/结构，可找回。
