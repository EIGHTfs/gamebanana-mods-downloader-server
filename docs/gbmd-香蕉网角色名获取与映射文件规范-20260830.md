# GameBanana 角色英文名获取 + 映射文件规范（快速上手）

> 版本：2026-08-30（角色名改用官方 Categories 接口；映射文件确立 roles/variants 新规范）
> 适用：gamebanana-mods-downloader-server（SA6400 NAS，服务端口 8642，代码在 `/volume6/Game.Patch N MOD/gamebanana-mods-downloader-server`）

---

## 一、这份文档解决什么问题

1. **角色英文名（"原名"）从哪拿、怎么拿**：绝区零等游戏在 GameBanana 上有"Character Skins"类根分类，下面每个角色是一个子分类（叫 category/SubCategory）。这些子分类的 `_sName` 就是**官方英文全名**（如 `Anton Ivanov`）。旧代码从"最新 mod 的 `_aSubCategory`"收集，会混进作者乱填的简写（如 `Anton`）导致一个角色两种名字并存——已废弃。
2. **映射文件（mapping/<游戏名>.json）怎么写才规范**：`roles` 只保留官方英文名（最完整、最规范），`variants` 是"规范中文 → 变体数组"（含中文简写和英文变体），供搜索归一化和目录合并使用。

## 二、获取角色英文名（唯一正确方法）

### 2.1 两步 API（都在 apiv11 上，无鉴权，直接 curl 即可）

**第 1 步：拿游戏的根分类（仓库）列表**

```
GET https://gamebanana.com/apiv11/Game/<gameId>/ProfilePage
```

响应里的 `_aModRootCategories` 数组就是根分类，取 `id` 和 `name`。

角色性根分类用正则过滤：`/characters|skins/i`（如 `Character Skins`、`Bangboo Skins`）。

> 绝区零 gameId = **19567**（json/gamebanana.com.json 里有）。Character Skins 根分类 id = **30305**。

**第 2 步：拉某根分类下的全部子分类（= 角色名单，A-Z 排序）**

```
GET https://gamebanana.com/apiv11/Mod/Categories?_idCategoryRow=<根分类id>&_sSort=a_to_z&_bShowEmpty=true
```

响应体：

```json
{
  "_aRecords": [
    { "_idRow": 30337, "_sName": "Anton Ivanov", "_nItemCount": 29, ... },
    ...
  ]
}
```

每条记录的 `_sName` 就是**官方英文名**（角色原名）。`_nItemCount` 是该角色下 mod 数。

> 绝区零 Character Skins（30305）下共 **60** 个角色，第一个就是 `Alexandrina Sebastiane`，安东是 `Anton Ivanov`（**不是**简写 `Anton`）。

### 2.2 代码位置

`server/lib/gb-api.js`：

- `fetchGameCharacterList(gameId, gameName, forceRefresh)` —— 角色列表主函数（本规范后约 369 行起）。
  - 缓存：内存 10 分钟 + 持久化 `json/role/<游戏名>.json`（`refresh=1` 强制重拉）。
  - GB 侧数据源：对每个角色性根分类调 `Mod/Categories`，收集 `_sName`。
  - 官方列表拿到后**合并本地 mapping `roles` 的英文 key**（roles 只剩规范名，不会混入简写）。
- `fetchGameInfo(gameId)` —— 拉 `_aModRootCategories`（内部缓存 10 分钟），返回值 `{ id, name, roots: [{id, name, itemCount, categoryCount}] }`。
- HTTP 封装 `fetchJson(url, headers, abortSec)`，`API_BASE = "https://gamebanana.com/apiv11/Mod"`（注意：**已经含 `/Mod`**，拼 URL 不要重复写 `/Mod/Mod`）。
- 页间隔 `sleep 350ms`，避免 400/429 限流。

### 2.3 第 3 步：写回角色缓存 JSON

`json/role/<游戏名>.json` 结构：

```json
{
  "gameId": 19567,
  "characters": ["Alexandrina Sebastiane", "Alice Thymefield", "Anton Ivanov", "..."],
  "at": 1725000000000
}
```

设置页的"🔄 重新获取角色"就是 `GET /api/gb-characters?game=...&refresh=1`。

### 2.4 重要陷阱（别踩）

| 做法 | 结果 |
|---|---|
| ❌ `Mod/Index` 翻页取 `_aSubCategory._sName` | mod 作者会把子分类乱填，混入 `Anton`/`Anby` 等简写、非官方名 |
| ❌ 直接 curl `https://gamebanana.com/mods/cats/30305` | 页面是 SPA JS 壳（43KB），HTML 里**没有**角色名 |
| ❌ `Category/30305/ProfilePage` 等页面类 API | 服务端 PHP 报错（缺 Model 文件），不可用 |
| ✅ `https://gamebanana.com/apiv11/Mod/Categories?_idCategoryRow=...&_sSort=a_to_z&_bShowEmpty=true` | 官方子分类（角色）名单，A-Z，含空分类 |

## 三、映射文件规范（mapping/<游戏名>.json）

### 3.1 文件结构（新规范，2026-08-30 起）

```json
{
  "warehouses": { "characters": "代理人", "skins": "代理人/.代理人", "weapons": "武器", "enemies": "敌人", "npcs": "NPC", "ui": "UI", "objects": "Objects", "models": "模型", "audio": "音频", "other": "其他" },
  "roles": {
    "Anton Ivanov": "安东·伊万诺夫",
    "Anby Demara": "安比·德玛拉",
    "Hoshimi Miyabi": "星见雅"
  },
  "variants": {
    "安东·伊万诺夫": ["安东", "Anton", "Anton Ivanov"],
    "安比·德玛拉": ["安比", "Anby", "Anby Demara"]
  }
}
```

### 3.2 三条铁律

1. **`roles`：key 只用官方（最完整）英文名 → 中文，一对一，不出现简写 key**
   - ✅ `"Anton Ivanov": "安东·伊万诺夫"`　❌ 没有 `"Anton": "安东"`
   - 中文名要规范（对照萌娘百科/绝区零百度百科），**不要假中文名**（例：`Nekomiya Mana` 是"猫宫又奈"，不是"猫又·玛娜"）。暂时拿不准的先按现有/目录名，后续可补。
2. **`variants`：key = 规范中文（roles 的值），value = 数组，数组 = [中文简写..., 英文变体...]**
   - ✅ `"安东·伊万诺夫": ["安东", "Anton", "Anton Ivanov"]`
   - 中文简写（如"安东"）、英文短名（"Anton"）都放进数组；数组里**必须包含规范中文和规范英文**。
3. **变体宁缺毋滥**：吃不准的变体直接删，不要求一次性补全。后期用 `POST /api/mapping/add-role` 追加。

### 3.3 规范中文/变体的来源

| 数据 | 来源 |
|---|---|
| 规范英文名 | 第 2 节官方 `Mod/Categories` 名单（权威） |
| 规范中文 | 优先磁盘 `代理人/` 目录里"英文 – 中文"文件夹名的中文部分（如 `Anton Ivanov – 安东·伊万诺夫` → `安东·伊万诺夫`）；其次旧 roles；其次旧 variants 反查；兜底用英文 |
| 中文简写 | 旧 variants 里"英文值能唯一解析到官方名"的 key（如 `安东`→`Anton`→`Anton Ivanov`） |
| 英文变体 | 旧 roles/variants 里英文短名，且**唯一命中**一个官方名（词级相等/前缀/后缀）才收；多候选（歧义）舍弃 |

**判据示例**：

- `Anton` → `Anton Ivanov`：词级相等（`Anton` 是 `Anton Ivanov` 首词）✅
- `Miyabi` → `Hoshimi Miyabi`：后缀命中（`Miyabi` 是尾词）✅
- `Anby`：`Anby Demara` 和 `Soldier 0 Anby` 都命中 → **歧义，舍弃**（宁缺毋滥）
- `Nekomata`：官方名单**没有**该名 → 无法解析，舍弃（它的中文"猫又"也顺带不进任何数组，等用户确认）

### 3.4 生成脚本逻辑（可复用）

生成脚本模式（Node，SA6400 上跑）：

```js
const normEn = s => String(s||"").toLowerCase().replace(/[^a-z0-9]/g,"");
const normZh = s => String(s||"").replace(/[\s·・]/g,"");
function isRelated(short, full) {          // 词级相等 或 前缀 或 后缀
  const sn = normEn(short), fn = normEn(full);
  if (!sn || !fn || sn === fn) return false;
  const ws = String(full).toLowerCase().split(/\s+/);
  return ws.some(w => normEn(w) === sn) || fn.startsWith(sn) || fn.endsWith(sn);
}
function resolveEn(short) {                // 唯一命中才返回，多候选返回 null
  const cands = official.filter(o => isRelated(short, o));
  if (cands.length === 1) return cands[0];
  const ex = cands.find(o => normEn(o) === normEn(short));
  return ex || null;
}
```

流程：

1. `official` = 第 2 节官方名单（每行一个英文全名）。
2. `roles[en] = 规范中文`（目录名 → 旧 roles → 旧 variants 反查 → 兜底 en）。
3. `variants[zh]` 初始化 `[zh, en]`。
4. 旧 roles 的英文 key 里，`resolveEn()` 唯一命中且非全等的 → push 进该角色的数组。
5. 旧 variants 的中文 key 里，`resolveEn(其英文值)` 唯一命中 → 该中文 push 进对应角色数组。
6. 规范中文 `·` 前段（如 `安东·伊万诺夫`→`安东`）且旧 variants 有同值 → push。
7. 去重；数组排序：中文在前、英文按字母序在后。

> 完整可用脚本当时在 `/tmp/zzz_gen2.js`（SA6400 上，重启后不保证保留），逻辑即上文。

## 五、历史背景（为什么会有这次改动）

- 2026-08-26 加 `fetchGameCharacterList`：从最新 mod 的 `_aSubCategory` 收集角色名（当时想"补全无近期 mod 的角色"）。
- 2026-08-30 用户给出页面 `https://gamebanana.com/mods/cats/30305`（官方角色名单页）指出"安东"获取不对 → 排查发现：
  1. 旧代码把 `Anton`（作者乱填的子分类）和 `Anton Ivanov`（官方名）都收进来了；
  2. 页面/ProfilePage 类 API 不可用（SPI JS 壳 + PHP 报错）；
  3. 前端实际调用 `Mod/Categories` 接口 → 用官方子分类名单替代。
- 同日用户要求重构映射文件：`variants` 值改数组（含中文简写），`roles` 只留规范英文；中文名暂按现有、假名（猫又·玛娜）修正，变体宁缺毋滥。
